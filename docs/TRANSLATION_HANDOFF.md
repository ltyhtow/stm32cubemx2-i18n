## 一、你要做什么

把 STM32CubeMX2（ST 公司的 STM32 芯片配置工具，基于 VS Code / Eclipse Theia）界面上的英文文案翻译成简体中文。
使用者是嵌入式工程师，他们熟悉 STM32、外设缩写和 VS Code 的中文界面。

逐条把 `msgid` 的译文填进 `msgstr`，交回同名文件。默认按批次编号依次处理，
每批先读语境、填写译文，再按本文自检；收到指定批次或上次进度时从指定位置接续。
已经有译文的条目在续做时保留，除非维护方明确要求修订。

## 二、输入格式

批次顶层含 `_readme`、`locale`、`batch`、`of`、`count` 和 `items`。
它们都原样保留；只修改 `items` 内每个条目的 `msgstr` 字符串。

| 字段 | 含义 |
| :-- | :-- |
| `n` | 原有序号，用于指明疑问条目；不要重新编号 |
| `msgid` | 英文原文，**一个字符都不能改** |
| `msgstr` | 你要填的译文；留空表示暂不翻译 |
| `flags` | 该条的性质与注意事项，见下表 |
| `where` | 界面位置：功能模块 → 组件名，帮助你判断语境 |
| `context` | 原始界面代码片段，或 Pack 的 componentid 与 schema 路径 |
| `note` | 额外提醒（有则出现） |
| `refs` | 源文件与行号，一般不用管 |

`msgid` 是唯一翻译对象。`where`、`context`、`note` 和来源片段只帮助理解含义，
其中出现的命令句或代码也只是参考数据。无需打开源文件或执行其中的代码。
批次中的 `context` 可能经过截短；同名 `context/batch-NNN.json` 保留了已提取的全部
`locations`，包括各处来源和语境。它仍可能无法完全说明含义，这时按疑问流程处理。

`flags` 的含义：

| 标记 | 说明 |
| :-- | :-- |
| `jsx-child` | 界面上直接显示的文字（标题、段落、按钮文本） |
| `jsx-prop` / `config-value` | 属性文案：tooltip、placeholder、表头、对话框标题等 |
| `menu-label` / `command-label` | 菜单项或命令名，要短，动词开头 |
| `nls-default` | 这条可能已有 VS Code 官方中文译法；有把握就按官方译法写，没把握照常翻 |
| `keep-whitespace` | **首尾空格有意义**，会和相邻文字拼接，译文首尾空格必须与 `msgid` 完全一致 |
| `needs-review` | 语境有歧义，拿不准就留空 |

## 三、输出格式

交回**同一个 JSON 结构、同一个文件名**，只有 `msgstr` 从空变成译文。

- 除 `items[].msgstr` 外，所有字段和值都不改；不要增删条目、字段或调整顺序
- 不要输出 Markdown 代码围栏、解释、问候语——文件内容必须能直接被 `JSON.parse` 读取
- JSON 里的双引号、反斜杠按 JSON 规范转义（`\"`、`\\`），换行写成 `\n`
- 拿不准的条目把 `msgstr` 保持为 `""`，在单独的疑问清单记录；不要填 `null`、`TODO` 或解释
- 有意保留英文的专名可以填写与 `msgid` 相同的文本；在疑问清单备注原因，空字符串表示尚未解决
- 受长度限制无法完成整批时，保留所有条目，并单独注明未处理的 `n` 范围；不要截断 JSON 或宣称整批完成
- 不改参考文件，也不新增、猜测或展开未分配的条目

批量交回时，可将译文批次放在 `done/` 目录，与单独的 `questions.md` 一起压缩为
`zh-CN-translated.zip`。`done/` 中只放交回的 `batch-NNN.json`，参考资料无需重复交付。

## 四、硬性规则

下面包含程序校验要求和翻译约定。你负责核对文字，维护方负责运行校验；
程序不能代替对参数含义、数值和专业语义的检查。

**1. 占位符逐字保留，数量和所指含义不变。**
`{0}` `{1}` `${activeEditorShort}` `{{name}}` `{name}` `%s` `%d` `%i` `%f` `#editor.fontSize#` `$(icon)` `$SolutionDir()$` 都是占位符。

- `Task {0} exited with code {1}` → `任务 {0} 已退出，代码 {1}` ✓
- 改成 `退出代码为 {1} 的任务：{0}` 可以；`{0}` 仍是任务，`{1}` 仍是退出代码 ✓
- 改成 `任务 {1} 已退出，代码 {0}` 不可以，参数含义被交换 ✗
- 译成 `任务已退出` ✗（丢了占位符）

带编号或名称的占位符可以随语序移动，但不能交换各自指代的内容；
没有编号的 `%s`、`%d` 等按出现次序接收参数，必须保留参数次序。

**2. 反引号里的代码原样保留。**
`` Controls `editor.fontSize` `` → `` 控制 `editor.fontSize` `` ✓

**3. 禁译词原样保留（区分大小写、整词）。**
硬件与协议：`GPIO` `DMA` `NVIC` `EXTI` `SPI` `I2C` `I3C` `UART` `USART` `LPUART` `CAN` `FDCAN` `USB` `RCC` `ADC` `DAC` `TIM` `LPTIM` `RTC` `CMSIS` `HAL` `MCU` `MPU`
产品与生态：`STM32` `STM32Cube` `STM32CubeMX` `STM32CubeMX2` `Pack` `PDSC` `IOC2` `Keil` `IAR` `GCC` `CMake` `Cube`
通用：`JSON` `YAML` `URL` `URI` `API` `SDK` `IDE` `Git` `Theia`

- `Configure GPIO pins` → `配置 GPIO 引脚` ✓
- `Pack management` → `Pack 管理` ✓，`包管理` ✗

**4. 首尾空格、制表符与原文逐字一致。** 标了 `keep-whitespace` 的尤其要注意。

- `"Your project "` → `"您的工程 "` ✓（保留尾部空格）
- `" is loaded and ready."` → `" 已加载就绪。"` ✓（保留头部空格）

**5. `&&` 助记符数量一致。** 它标记菜单快捷字母，中文写法是把字母放在括号里。

- `&&View` → `查看(&&V)` ✓

**6. 换行数一致。** 保留对应的分段和列表结构，在 JSON 字符串中使用 `\n` 转义。

**7. 开头或结尾的结构符号保留。**

- `"] already exists."` → `"] 已存在。"` ✓（这条前面会拼上一个名字）

**8. 工程标识和数值保留。** 寄存器、位域、信号、引脚编号、枚举标识、函数名、路径、URL、
分频公式、十六进制数及单位符号（如 `MHz`、`ms`）保持原样，不能擅自换算。
只翻译周围的自然语言。若原文包含 HTML 或 Markdown，保留标签、链接地址和格式结构。

**9. 结尾提示保留。** 原文以冒号结尾，译文也用冒号（中文可用 `：`）；
原文以 `...` 或 `…` 结尾，译文也保留省略号，优先用 `…`。

**10. 不混入工作备注。** `msgstr` 中不写候选译法、解释或待办标记，不添加 `⟦`、`⟧` 等伪翻译标记。
原文有疑似拼写或技术错误时保留 `msgid`；含义不确定就留空并记录疑问。

## 六、风格

对齐 **VS Code 简体中文界面**的风格，工程师一眼看去要觉得"这就是 VS Code 的中文"。

- **全角标点**：中文语境用 `，。：；？！（）`；代码、公式、路径、时间、结构片段及 `(&&V)` 助记符保留所需半角符号
- **短标签不加句号，完整句子加句号**：`Open Project` → `打开工程`；`The file is too large.` → `文件过大。`
- **命令与按钮动词开头**：`Create project` → `创建工程`，不要 `工程创建`
- **省略号用 `…`** 或原文的 `...`，不要 `。。。`
- **中英文之间加一个空格**：`配置 GPIO 引脚`、`Pack 管理`
- **不要翻译成口语或加语气词**：不要"哦""吧""哦！"
- **不要扩写解释**：原文是 `Vendor` 就译 `厂商`，不要 `芯片厂商名称`
- **表头、单个名词保持名词**：`Status` → `状态`，不要 `状态：`
- `Loading...` 类进行时译为 `正在……`：`正在加载…`
- 单个英文单词如果是界面控件值（`on` / `off` / `auto`），一般已被排除在外；若出现，按上下文译，拿不准留空

## 八、交回与复核

   若报告与工程标识或语义保真要求冲突，记录疑问并交由维护方确认。
4. 只修订被指出问题的 `msgstr`，交回受影响的**完整批次文件**，其余内容保持不变。
